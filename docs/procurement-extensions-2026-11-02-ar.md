- حفظ الأصفار والأكواد الطويلة النصية. ترفض الأرقام الطويلة غير الآمنة والصيغ؛ تاريخ غير مفهوم يسمح بتحذير وانتهاء افتراضي صريح، والتاريخ المنتهي الصالح لا يُستبدل.
- تكلفة موجبة وحساب عشري دقيق، وعدّ الفئات المميزة مستقلاً عن عدد الملفات.
- سياسة اختيارية للإرسال قبل الاعتماد، مع سجل معلّق/معتمد/معاد للتصحيح/مرفوض وإعادة إرسال بإصدار جديد. إدارة واحدة حالياً، وليست صلاحيات موظفين متعددة.
- التحقق مجدداً من السعر والفئة والتكرار عند الاعتماد، وتشفير أكواد الطلبية، ومنع إعادة إضافة المخزون عند تكرار الطلب أو انقطاع الاتصال.

## ربط الشركات وطلبات العملاء

إعداد مستقل للتوب أب والرابعة من الداشبورد: مفتاح مشفّر، تفعيل القراءة، إصدار للتعديل، وحقل فارغ يحافظ على المفتاح. تغيير المفتاح يتطلب سبباً ويُمنع أثناء وجود تنفيذ غير محسوم، ويلغي الكتالوج القديم وربطه. لا يعاد المفتاح للمتصفح أو التخزين المحلي.

تحديث كتالوجات الشركات وربط عروضها بمنتجات وأسعار فاتيا. كتالوج الرابعة مرتبط بالمحافظة؛ نجاح القائمة الفارغة يعطل العروض السابقة المعنية، وفشل الاتصال يحافظ على آخر بيانات دون اعتبارها محدثة. الرصيد موثق للتوب أب فقط، ولا نفترض رصيداً للرابعة.

مسار التنفيذ المبرمج: طلب مستفيد واحد → انتظار تأكيد دفع موثوق → طابور خادم → تحقق سعر وتوفر وأهلية → تنفيذ واحد → تسليم أو مراجعة. لا يستطيع العميل أو زر إداري إعلان نجاح الدفع. الحجز ينتهي بعد 15 دقيقة دون دفع.

التوب أب يتطلب الرقم وتأكيده. الرابعة تحفظ holdToken قبل purchase؛ Premium يتطلب بيانات المشترك ومحافظته ونتيجة تسليم صريحة. الأدلة والأكواد مشفّرة، والعميل المالك فقط يستطيع استلام الكود بعد تأكيد الدفع والتسليم.

الاستجابة المفقودة أو غير الحاسمة تذهب للمراجعة دون إعادة شراء تلقائي. مراجعة الرابعة تستخدم سجل معاملات للقراءة فقط؛ غياب PIN لا يعد تسليماً. لا يوجد زر إعادة POST مالي أو رد أموال وهمي. تكلفة التوب أب الفعلية غير معروفة إن لم يثبتها الرد؛ لا يعرض ربحاً مفترضاً.
