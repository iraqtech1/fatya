# رفع الطلبيات والتوب أب والرابعة

مرجع المتطلبات: دليل المستخدم بتاريخ 28 أكتوبر 2026. عناوين الشركات وعقودها في الدليل أمثلة من نظام آخر، وليست اعتماداً تشغيلياً لحساب فاتيا. لا تُنسخ جلسات Sanctum أو مسارات `/stock` من ذلك النظام إلى فاتيا؛ تبقى مصادقة فاتيا الإدارية مستقلة.

## الوظائف المضافة

- `/admin/stock-orders`: رفع TXT وCSV وTSV وXLSX أو لصق صفوف، وربط أعمدة PIN والسيريال والانتهاء، وتحديد البطاقة والفئة وتكلفة الوحدة والمجهز والمصدر والمحافظة. يقرأ XLSX الورقة الأولى فقط، ويرفض المعادلات والأرقام غير الآمنة. يحافظ على أصفار تنسيق مثل `000000`، وتبقى الأكواد من 16 خانة فأكثر نصاً في الملف الأصلي. لا يمكن استرجاع أصفار أو أرقام فقدها Excel قبل الرفع. يقبل الانتهاء تاريخ Excel الأصلي، أو الرقم التسلسلي لتاريخ Excel بنظام 1900/1904، أو `YYYY-MM-DD` أو يوم/شهر/سنة، ويرفض التواريخ المستحيلة مع رقم الصف.
- معاينة خادمية لـ50000 بطاقة و200 سطر فئات كحد أقصى، وفحص التكرار والصلاحية، مع تحذير للتاريخ غير المفهوم. تاريخ الانتهاء اختياري. المعاينة مشفرة في الخادم وصالحة 15 دقيقة ولا تعرض PIN في الرد.
- الاعتماد المباشر من الإدارة بعد تأكيد استبعاد المرفوض، مع رقم مراجعة وبصمة معاينة ومفتاح منع تكرار. تغير البيانات أو الأسعار أو الصلاحية يرفض المعاينة القديمة. لا تدخل البطاقات في المخزون قبل الاعتماد. الملفات والمفاتيح لا تحفظ في Git.
- حفظ تكلفة البطاقة ودفعتها وانتهائها. لا تُحجز بطاقة منتهية، ويمنع تسليم بطاقة انتهت بعد الحجز. تُحفظ تكلفة البيع وربحه قبل الرسوم عند تسليم الطلب المؤكد، وتبقى تكلفة المخزون القديم مجهولة. تعرض الإدارة هذه القيم ويمنع كشفها في حالة العميل العامة.
- `/admin/digital`: حالة ربط التوب أب والرابعة، جلب الكتالوجات والمجموعات، رصيد التوب أب، المحافظات العادية ومحافظات Premium، فحص أهلية الرقم مع تأكيده، وربط معرف الشركة بالفئة المحلية وسعر البيع. يحمي رقم المراجعة وبصمة الكتالوج من حفظ نسخة مختلفة أو قديمة.
- كتالوج الشركة لا ينشر فئات افتراضية عند فشل الاتصال. الربط الجاهز في `digital_offers` إعداد مستقل للإطلاق؛ لا يغيّر مصدر تنفيذ المنتجات الحالية أو يحوّل مخزونها إلى API تلقائياً.

## المصادقة والاتصال

المسارات الجديدة تحت `/api/admin/procurement/` تتطلب جلسة الإدارة الحالية وطلبات JSON وترويسة `X-Fatya-Request: 1` عند الكتابة. لا تستخدم مفتاح الشركة للدخول إلى المخزون. لا يُكشف المفتاح في API الحالة أو أخطاء المزود.

بيانات الخادم الخاصة:

```dotenv
TOPUP_ENABLED=false
TOPUP_BASE_URL=https://masal-co.com
TOPUP_API_KEY=
RABIAA_ENABLED=false
RABIAA_BASE_URL=https://tryapi.nojoomalrabiaa.com/api/v2
RABIAA_API_KEY=
```

بعد تأكيد حسابات فاتيا والعنوان من المزود، توضع المفاتيح في `.env` الخاص وتُفعّل القراءة لكل مزود. العناوين مقيدة بالمضيفين المذكورين؛ اعتماد مضيف جديد يتطلب مراجعة الكود وقائمة السماح. لا يتبع الاتصال التحويلات، ويستخدم 8 ثوان للاتصال و25 للطلب. لا ينفذ هذا القسم طلب شراء أو حجز مالي، ولا يعيد POST مالياً تلقائياً.

## حدود المرحلة الحالية

لم يتضمن الملف مفاتيح حسابات تشغيلية أو عقد بوابة دفع. لذلك نُفذ مسار إدارة الاستيراد والقراءات والربط والتسعير، واختُبر بمزود وهمي مع منع الشبكة الخارجية. **تنفيذ شحن التوب أب وhold/purchase للرابعة، ومراجعة سجل عملياتها والاسترجاعات، وإيصال Premium، غير مفعّل في هذه المرحلة**. لا توجد أزرار إدارية تتجاوز تأكيد الدفع أو تنشئ خصماً يدوياً لدى المزود.

إكمال التنفيذ المالي يتطلب توثيق الحساب المعتمد ومفاتيحه، عقد نجاح/فشل فعلياً، وربطه بتأكيد دفع موثوق، ثم سجل عمليات منفصل للدفع والتنفيذ والتسليم ومنع التكرار وحفظ الأدلة المشفرة. لا يكفي HTTP 200 لإثبات نجاح العملية. تبقى النتيجة غير الحاسمة للمراجعة دون شراء جديد. لا يوفر الدليل استعلاماً مستقلاً للتوب أب أو استرجاع PIN مستقلاً للرابعة أو رصيداً مالياً موثقاً للرابعة.

سياسة PIN في مخزون فاتيا الحالي مطلوبة، والسيريال اختياري لكنه فريد على كامل المخزون. لم تُرخ هذه القيود إلى سياسة مختلفة لكل فئة أو إلى فرادة السيريال ضمن فئة فقط، للحفاظ على سلامة البيانات الحالية. لا توجد صلاحيات موظفين أو دورة موافقات متعددة؛ النظام الحالي إدارة واحدة تعتمد مباشرة. تبقى واجهة الاستيراد القديمة محدودة بـ5000 صف ومتوافقة، دون تكلفة مفترضة.

## النشر

يشمل التحديث migration `2026_10_28_000001_add_procurement_and_digital_catalog` وخمسة جداول جديدة وثلاثة أعمدة في المخزون. يؤخذ backup متسق للقاعدة وAPP_KEY، ثم يرفع الباك والواجهة المبنية وتنفذ `php artisan migrate --force`. لا تغير APP_KEY أو بيانات حسابات الإنتاج. مفاتيح المزودين اختيارية للرفع؛ تبقى القراءة غير مفعلة إلى إعدادها.

الاختبارات تشمل عدم تغيير المخزون بالمعاينة، التشفير والأصفار، التكرار، التكلفة الدقيقة والربح، الصلاحية، تأكيد الاستبعاد، المعاينة القديمة وإعادة الطلب نفسه، صلاحيات الإدارة، منع كشف التكلفة للعميل، فحص الأهلية المنطقي الصارم، أرقام المراجع الطويلة، تقييد المضيفين، وعدم إرسال شراء مالي.

فحص الدفعة الكبيرة: نجح اعتماد 50000 بطاقة في قاعدة اختبار SQLite معزولة؛ استهلاك ذروة مجموعة PHPUnit كان 164 MB. تحفظ أدلة المعاينة كقطع مشفرة لتجنب حد TEXT والحزم الكبيرة في MariaDB. يوصى بذاكرة PHP مقدارها 512 MB لهذه الأحجام، مع اختبار حدود الاستضافة قبل رفع ملف حقيقي كبير.

## إصلاحات 29 أكتوبر 2026

تُلغى معاينة الطلبية وموافقة الاستبعاد ومفتاح الاعتماد فور تغيير أي حقل أو ملف أو ربط أعمدة أو إصدار بيانات الخادم. لا تستطيع استجابة متأخرة إعادة معاينة أُلغيت. لا يمكن معاينة نص ملصوق جديد قبل الضغط على «قراءة النص». عند تعارض إصدار الخادم، تُحدّث البيانات وتُطلب معاينة جديدة مع حفظ حقول الطلبية.

تحديثات الأمان ضمن السلسلة المتوافقة: Vite إلى 6.4.5 وSymfony Mime إلى 7.4.22، مع تحديثات التبعيات المصححة في ملفات القفل. تدقيق Composer بلا تنبيهات وقت التحديث. بقي تنبيه منخفض لمكتبة البناء `deepmerge` عبر Workbox/PWA، [GHSA-gcqx-w48m-w2h4](https://github.com/advisories/GHSA-gcqx-w48m-w2h4)، بلا إصدار مصحح منشور وقت الفحص؛ لا يُستخدم `npm audit fix --force` لأنه يقترح تخفيض PWA إلى إصدار قديم. لا يتطلب هذا الإصلاح migration جديدة أو تغيير مفاتيح التشفير.
