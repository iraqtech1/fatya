# ربط تأكيد لرموز واتساب والإشعارات

يستخدم الخادم وضع التوصيل في تأكيد: يولد رمزاً من ستة أرقام، يحتفظ ببصمته لخمس دقائق وبحد خمس محاولات، ويرسل الرقم بصيغة +964 مع IP المستخدم العام واسم التطبيق. لا تظهر الرموز في إنتاج الويب. إعداد `REQUIRE_REGISTRATION_OTP=true` يمنع إنشاء الحساب قبل التحقق ويحفظ بصمة كلمة المرور فقط في التحدي. الدخول المعتاد بكلمة المرور باقٍ؛ استرجاعها يتم بالرمز.

إعدادات الخادم الخاصة: `OTP_PROVIDER=takeed` و`TAKEED_API_KEY` و`TAKEED_APP_ID` و`TAKEED_TARGET`. احتفظ بها في `.env` خارج المجلد العام. حافظ على APP_KEY الحالي. لا تضع المفتاح في Git أو `VITE_*`.

بعد رفع migration الخاص بتتبع دفع الإشعارات نفذ `php artisan migrate --force`. تبقى الإشعارات الداخلية محفوظة حتى عند فشل الإرسال الخارجي. يشغل Cron الموجود `schedule:run` كل دقيقة؛ أضيفت مهمة `fatya:push-deliver` لتسليم الإشعارات المحفوظة بعد تثبيت معاملة قاعدة البيانات، مع محاولات مؤجلة ومدة حجز تمنع تزامن العمال. لا يعيد الترحيل إرسال الإشعارات القديمة. تستخدم إشعارات الجهاز وصفاً عاماً دون الأكواد أو تفاصيل الطلب الخاصة.

واجهة حسابي تتيح تفعيل/إيقاف إشعارات الجهاز بعد ضغط المستخدم، وتسجّل هويته باسم مستعار HMAC خاص به. يحذف تسجيل الخروج اشتراك المتصفح المحلي لمنع وصول إشعارات الحساب السابق. العامل داخل `/push/` مستقل عن عامل PWA. ملفات SDK المنسوخة من تأكيد في `public/push/` هي النسخة الرسمية v1 وقت الربط؛ عند تحديثها راجع التوافق والاختبارات.

أضف `https://fatyh.net` إلى نطاقات الويب المسموحة في تطبيق تأكيد. إذا فُعّل التحقق من الهوية في لوحة تأكيد، ضع سر الهوية في `TAKEED_IDENTITY_SECRET`. على iPhone يتطلب Web Push إضافة الموقع للشاشة الرئيسية. دليل تأكيد يستخدم Web Push للويب وPWA دون Firebase؛ مفتاح Firebase Admin SDK مطلوب لإعداد تطبيق Android/iOS أصلي لدى المزوّد، وليس للنشر في المتصفح.

كارت رصيد OTP في رئيسية الداشبورد يقرأ `/api/admin/otp/balance` المخصص لجلسة الإدارة فقط، ويعرض الرصيد الفعلي وآخر تحديث، ويتيح تحديثاً يدوياً. التخزين المؤقت 30 ثانية والتحديث التلقائي كل دقيقة عند ظهور الصفحة. الخطأ لا يُحوَّل إلى رصيد صفر.

التحقق المحلي: اختبارات MessagingTest تغطي تأجيل إنشاء الحساب، صحة ترويسة المزود وصيغة الهاتف وIP، عدم كشف الرمز أو كلمة المرور، رفض إعادة استعمال الرمز، فشل الرصيد، عزل جمهور الإشعارات وإعادة المحاولات، وحماية الرصيد الإداري. لا ترسل هذه الاختبارات رسائل فعلية.

المراجع الرسمية: https://control.takeed-iq.com/docs/otp و https://control.takeed-iq.com/docs/quickstart-web و https://control.takeed-iq.com/docs/notifications.
