# متطلبات ربط Qi عبر GINI Bridge

تمت مراجعة الوثائق الرسمية بتاريخ 7 تشرين الثاني 2026:

- https://bridge.gini.iq/docs
- https://bridge.gini.iq/docs/authentication
- https://bridge.gini.iq/docs/onboarding

الربط الموصوف موجّه لتطبيقات مصغرة داخل Super Qi. يلزم تطبيق تاجر لدى GINI، وحساب Qi Workspace ومعرّف mini-app، وإتاحة التطبيق لمختبرين مسجلين. تصدر بيئتا Sandbox والإنتاج مفاتيح منفصلة؛ لا يكفي رابط الوثائق لتفعيل التحصيل.

يوقّع Laravel الطلبات باستخدام HMAC-SHA256 للبايتات الفعلية للجسم مع API key والطابع الزمني وnonce. الدفع يتطلب أيضاً bearer خاصاً بالعميل عبر مسار المصادقة الخاص بالمنصة. تبقى الأسرار والرموز الحساسة في الخلفية، ولا تُضاف إلى حزمة Vue أو Git.

العمل المطلوب بعد توفير الإعدادات: مسار callback HTTPS مسجل لدى المزود، ربط transaction_uuid بالطلب، تحقق توقيع webhooks والوقت ومنع التكرار، مطابقة المبلغ والعملة والطلب قبل التسليم، وإعادة المحاولة بمفتاح idempotency ثابت وnonce جديد. يجب فحص النتيجة الموثوقة وتسوية الاسترجاع؛ الرجوع من واجهة الدفع وحده لا يثبت التحصيل.

تنص الوثائق على أن Sandbox يستخدم حسابات Super Qi حقيقية وأن الدفع الإلكتروني التجريبي محدود بدينار واحد ويحرك أموالاً حقيقية. لم تُنفذ معاملة أو إنشاء حساب تاجر أو إرسال بيانات شخصية أثناء المراجعة. الاختبارات المالية تحتاج إجراءً مستقلاً من صاحب الحساب.

نحتاج من التاجر إعدادات تطبيق GINI وبيئته، API key وsecret عبر إعدادات الخادم الآمنة، معرّف mini-app، عنوان callback المعتمد، تفاصيل وسيلة الدفع والعمولات المتاحة وقائمة مختبرين. لم يُغيّر إصدار تحسين الأداء والمزامنة حالة الدفع الحالية.
